# Self Research

Self Research is a small, evidence-driven method for building and revising a provisional personal model. It keeps **Evidence → Model → Guidance** separate, so a vivid story or an AI interpretation cannot silently become identity.

## The v0.1 loop

```text
bounded question → evidence/source distinction → case reconstruction
→ descriptive observations → provisional hypotheses
→ competing explanation check → bounded counterexample search
→ owner review → model review + method review
```

A cycle stops when its stated stopping condition is met. It should leave clear answers about what was learned, what remains uncertain, what changed, and what to test next.

## What it is / is not

It is a reusable research method and agent execution interface. It is not a personality test, diagnosis, deterministic life plan, diary replacement, raw archive, LifeOS, data warehouse, website, spreadsheet product, digital twin, or finished personal assistant. v0.1 deliberately validates the discipline on a small number of private real-life cases; it does not reconstruct a whole life.

## Why Evidence → Model matters

Evidence records what happened, what was remembered, what was expressed, and what artifacts support it. The Model is an explicitly provisional interpretation that can be strengthened, contested, or retired. Guidance turns supported claims into questions, warnings, or experiments—never destiny.

## Public / private boundary

This repository contains the method, contract, and generalized examples—not a person’s private model. Raw transcripts, private chats, family or social material, case files, sensitive hypotheses, and personal evidence dumps stay outside the public repository.

## Quickstart

1. Read [`PRODUCT.md`](PRODUCT.md) for purpose and scope.
2. Read [`RESEARCH_CONTRACT.md`](RESEARCH_CONTRACT.md) before forming or promoting claims.
3. Give an agent [`SKILL.md`](SKILL.md) when explicitly invoking Self Research on a bounded topic.
4. Use [`docs/review-protocol.md`](docs/review-protocol.md) for cycle and method review.
5. Keep private evidence private; publish only generalized, de-identified method lessons with owner approval.

`PRODUCT.md` defines what the product is for. `RESEARCH_CONTRACT.md` defines how claims may be formed and changed. `SKILL.md` is the concise execution interface. The review protocol governs evidence-backed evolution.

## v0.1 stopping condition

The first validation cycle will reconstruct a small set of already-discussed private cases, produce only a few candidate cross-case hypotheses, perform at least one competing-explanation or counterexample check, complete both Model Review and Method Review, and decide whether the contract needs revision. No future surface is promised before that validation.
